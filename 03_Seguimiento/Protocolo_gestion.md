# Protocolo de gestión y monitoreo en GitHub

## Herramientas
- README: propósito, alcance y enlaces principales.
- Issues: actividades, entregables, responsables, dependencias y criterios de aceptación.
- GitHub Projects: tablero de estados, prioridades y fechas.
- 02_Evidencias: productos autorizados e índice de trazabilidad.
- 03_Seguimiento: plan, indicadores, riesgos y decisiones.

## Estados sugeridos para el Project

| Estado | Regla de uso |
|---|---|
| Pendiente | Actividad registrada, aún no iniciada |
| En curso | Trabajo iniciado y avance descrito |
| Bloqueada | Impedimento concreto y acción de desbloqueo identificados |
| En revisión | Entregable disponible y pendiente de validación |
| Finalizada | Criterio de aceptación satisfecho y evidencia comprobada |

El estado abierto/cerrado del Issue no sustituye el campo Status del Project. Incorporar los Issues al Project existente; su creación no garantiza que queden añadidos automáticamente.

## Rutina de revisión
En cada corte acordado por el equipo:
1. Revisar actividades próximas, vencidas, bloqueadas y en revisión.
2. Solicitar avance verificable a cada responsable.
3. Comprobar dependencias y actualizar fechas solo con acuerdo.
4. Revisar entregables frente al criterio de aceptación.
5. Enlazar evidencia autorizada desde el Issue y actualizar el índice.
6. Registrar decisiones que cambien alcance, secuencia, cobertura o criterios.
7. Revisar riesgos e incidencias.

La frecuencia del corte debe acordarse; este protocolo no presupone una reunión semanal.

## Formato breve de actualización
- Fecha de corte:
- Avance verificable:
- Pendiente o bloqueo:
- Acción siguiente, responsable y fecha acordada:
- Evidencia autorizada:

## Cierre y control de versiones
Cerrar un Issue solo cuando el entregable está disponible, cumple el criterio, tiene evidencia accesible y autorizada, y cuenta con las validaciones requeridas. Mantener abierto o reabrir si falta soporte. El número de Issues cerrados no equivale a impacto social.

Usar nombres consistentes con código de actividad, tipo, fecha y versión. Mantener una versión vigente identificable y conservar el historial mediante commits.
